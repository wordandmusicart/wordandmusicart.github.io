# Аудит wordandmusic.art — 25.09.2026

## Короткий brief

Мета: перевірити живу сторінку концерту, прибрати підтверджені технічні помилки й сміття з публікації без зміни затвердженого вигляду та файлів зображень. Критерій: працюють квиткове й контактні посилання, немає обрізання на перевірених екранах, службові файли не публікуються, афіші та їхні метадані залишаються побітово незмінними.

Терміни: **афіша** — `concert-desktop.png` або `concert-mobile.png`; **публікація** — вміст артефакту GitHub Pages з `dist/`; **вихідні файли** — репозиторій із тестами, документацією й інструментами.

## Якість і перевірки

- Жива головна, `robots.txt`, `sitemap.xml`, Eventmate, Instagram, YouTube і файли афіш відповідали HTTP 200 на момент аудиту.
- Chrome: 1440×900, 390×844, 320×568, 1024×600, 390×621, 375×667, 700×900, 768×1024 та 844×390 — афіша й контакти видимі, горизонтального переповнення немає. На 390×844 знизу багато білого простору; це дизайнерський вибір, не обрізання.
- axe-core на живій і локальній версіях: 0 автоматично виявлених порушень WCAG 2 A/AA, 2.1 A/AA, 2.2 AA. Контраст фонового градієнта потребує ручної оцінки; автоматична перевірка позначила його як inconclusive.
- Скріншоти локальної збірки на 1440×900, 390×844 і 320×568 побітово збігаються з живою сторінкою. Жодної візуальної зміни.
- Всі PNG та SVG у `assets/` мають ті самі Git blob SHA, що й `HEAD`. Афіші зберегли PNG-метадані `Software: Adobe ImageReady` та `pHYs`; у цих файлах EXIF/XMP/ICC-профілі не виявлено.
- `npm test` пройшов на чистій копії Git з локальними змінами. Пряме збирання в папці Google Drive зависало на читанні `sitemap.xml` через File Provider; файл у Git читається нормально. Lighthouse у цьому середовищі завершився `NO_FCP`, тому оцінку продуктивності не заявляю.

## Рішення та відкриті питання

- Збірка використовує явний перелік публічних файлів; усі поточні зображення залишаються доступними, а вихідні документи й інструменти не завантажуються в Pages. CI запускає тести перед публікацією.
- Оптимізація та вибір роздільності афіш залишаються відкритими: додаткові варіанти, про які повідомив користувач, не були в `assets/` цього репозиторію. Потрібно окремо звірити їхні шляхи й метадані перед будь-яким підключенням.
- Зміни підготовлено локально; жива версія залишатиметься колишньою до публікації.
